## API fields and response shapes

`GET /employees` accepts `page`, `limit`, `search`, `departmentId`, `status`, and `role`. The response is `{ data: EmployeeDto[], total, page, limit }`, not the shared `PaginatedResponse<T>` envelope.

Creation uses `fullName`, `email`, `roleCodes`, and optional `employeeCode`, `phone`, `dateOfJoining`, `departmentId`, `designationId`, `managerId`. The form combines first and last names into `fullName`; no unsupported name fields are sent. Email is trimmed and lowercased. Empty optional fields are omitted. Employee codes are generated by the backend when omitted.

Creation returns `{ employee, tempPassword }`. The mutation function sends the password directly to component state and returns only `employee` to TanStack Query. The password is cleared when the dialog closes or its page unmounts, and is never stored in query/mutation data, browser storage, or application logs. The modal supports copying, displays a one-time warning, traps focus, and ignores backdrop clicks.

Update uses `fullName`, `phone`, `dateOfJoining`, `departmentId`, `designationId`, and `managerId`. Email, code, and role assignment are read-only in this dialog because they are not fields in `UpdateEmployeeDto`. Empty joining dates are omitted rather than clearing existing dates, matching the DTO's non-null date contract. Masked phone/date values are not sent back as blanks.

List/detail fields include `id`, `employeeCode`, `fullName`, `email`, `departmentName`, `roles`, `status`, and the optional profile/organization fields defined by `EmployeeDto`. Masked/missing display values use an em dash.

Lookups use `GET /organization/departments`, `GET /organization/designations`, `GET /roles`, and paginated active `GET /employees` requests for potential managers. Organization/role endpoints return arrays.

## Permissions

- `employees.view`: list route, sidebar, employee lookup.
- `employees.create`: add route and Add employee button.
- `employees.edit`: editing in the employee detail modal.
- `employees.deactivate`: both deactivate and reactivate, matching the controller.
- `employees.view_sensitive`: sensitive profile field editing; viewing self also permits it.
- `organization.view`: department/designation lookup requests.
- `roles.view`: role catalog lookup requests.

The prompt assumed AuthProvider exposed user/permissions and existing permission helpers. Those are absent in this checkout. The added helpers read the existing `/auth/me` endpoint through TanStack Query, gated by existing authentication status, without changing auth/session behavior. UI checks are for navigation and action visibility; server permissions still decide access.

## Assumptions and open decisions

- First and last name are both required by the requested UI; the backend itself requires only a nonempty `fullName`.
- Joining date is optional, as in the DTO, and the UI additionally rejects future dates.
- `EMPLOYEE` is the initial selected role. Users without `roles.view` can use the default role; other role options require catalog access.
- Lookup endpoints may require permissions beyond `employees.create`. Optional organization/manager fields are disabled without lookup access. Failures are displayed with retry controls.
- Backend permission scopes determine which employees are returned; the UI does not attempt its own record-scope filtering.
- Changing an existing employee's roles is outside the profile update dialog; that uses a separate backend action and permission.
- No new backend fields or migrations were needed.

## Validation

`npm run typecheck` passed for all workspaces. `npm run test` passed with 22 web tests and 22 API tests (44 total). The production web build and targeted ESLint checks also passed. Docker images were not rebuilt in this session.

Tests exercise directory rows/empty/error states, filters and debounced URL parameters, pagination, action visibility, status-change confirmation, editing, required/future-date validation, duplicate-email errors, temporary-password visibility/copy/focus/clearing, and exclusion of the secret from mutation-cache data. Existing logout regressions remain part of the test run.

## Docker rollout

Rebuild the images to include frontend changes:

```powershell
docker compose up -d --build
```

Hard-refresh the browser, then open `http://localhost:8080/employees` using an account with `employees.view`. Add Employee is at `/employees/new` and requires `employees.create`.
